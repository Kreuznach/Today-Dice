# 오늘의 주사위 — 프로덕트 기획서 (PRD)

> 작성일: 2026-04-03  
> 버전: v0.1 (MVP 초안)  
> 대상 플랫폼: Toss in App WebView 미니앱  

---

## 1. 서비스 정의

> **"오늘의 운을 10초 만에 확인하는 1일 1회 AI 주사위 대결"**

사용자가 이 앱을 켜는 이유:
- 어제 졌으니까 오늘은 이겨야 한다.
- 3연승 중인데 오늘도 이겨서 기록을 이어가야 한다.
- 그냥 오늘 운이 어떤지 궁금하다.

경품, 포인트, 쿠폰, 현금성 보상은 전혀 없으며,  
**재미와 연속 기록** 자체가 유일한 동기다.

---

## 2. Toss in App 적합성 분석

### 2-1. 짧은 세션 (10~15초 완결)

| 항목 | 내용 |
|------|------|
| 진입 ~ 플레이 완료 | 10~15초 이내 |
| 필요한 조작 수 | 버튼 1회 탭 |
| 추가 학습 필요 여부 | 없음 (주사위 = 즉시 이해) |

Toss in App 사용자는 이미 금융 목적으로 앱에 진입해 있다.  
부담 없는 초경량 서비스만 체류 시간을 늘릴 수 있다.

### 2-2. 매일 1회 방문 동기

- "오늘 아직 안 굴렸다"는 미완료 상태가 재방문을 만든다.
- 연승 기록이 존재하는 한 "끊기 싫어서" 매일 방문한다.
- 플레이 자체가 30초 미만이라 부담이 없다.

### 2-3. 광고 구조 적합성

- 결과가 마음에 안 들 때 자발적으로 광고를 선택한다.
- 강제 광고나 팝업 없이 **선택형 진입**으로 사용자 경험을 해치지 않는다.
- 광고 → 재대결 플로우가 논리적으로 자연스럽다.

### 2-4. 기록 경쟁 (현금성 보상 없이 리텐션 설계)

- 연승 랭킹 TOP5가 "이기고 싶은" 동기를 만든다.
- 보상이 없어도 기록 자체가 보상이다.
- 사행성 우려 없이 경쟁 구조 구현 가능.

### 2-5. 기술적 적합성

- WebView에서 JS만으로 동작하는 초경량 단일 페이지 앱.
- Supabase로 인프라 최소화, 서버리스로 관리 부담 없음.
- 복잡한 WebSocket이나 실시간 통신 불필요.

## 4. 게임 규칙 제안

### 4-1. 기본 규칙

```
주사위: 1개, 1~6 정수, 균일 확률
사용자 숫자 > AI 숫자  →  승리
사용자 숫자 < AI 숫자  →  패배
사용자 숫자 = AI 숫자  →  무승부
```

- AI 주사위 값은 **서버에서 생성** (클라이언트 신뢰 금지)
- Math.random() 기반 의사난수로 충분 (베팅 없음)

### 4-2. 무승부 처리 방식 (추천안)

> **무승부는 연승/연패 스트릭을 초기화하지 않는다.**

| 상황 | 결과 |
|------|------|
| 3연승 → 무승부 → 1승 | 연승 3 유지 후 무승부 삽입, 그 다음 승리로 다시 1승 시작 |
| 연승 진행 중 무승부 | 연승 종료, 무승부 스트릭 0→1 |
| 연패 진행 중 무승부 | 연패 종료, 무승부 스트릭 0→1 |

**이유:**
- 단순히 "초기화"만 하면 무승부가 연승을 끊는 불쾌함 발생
- 무승부 = 중립 기록으로 취급하면 스트릭 관리가 명확해짐
- 연승/연패/무승부 스트릭을 별도 추적하면 랭킹 다양성도 확보됨

> **검토 필요:** 무승부가 "연승을 끊느냐 vs 중립이냐"는 출시 전 A/B 결정 필요.  
> MVP에서는 **연승 끊는 방식(단순화)** 으로 먼저 시작하는 것도 가능.

### 4-3. 광고 후 재대결 구조 (UX 관점)

```
[1차 플레이] → [결과 표시]
                     ↓
          아직 재대결 안 했다면
                     ↓
          "오늘 한 번 더 굴려볼 수 있어요" 버튼 노출
                     ↓
          [버튼 탭] → 광고 시청 (15~30초)
                     ↓
          광고 완료 확인 → [서버에 재대결 요청]
                     ↓
          서버: has_rematch 체크 → 새 AI 주사위 → 결과 판정 → 저장
                     ↓
          [최종 결과 표시] → 되돌리기 불가, 오늘의 확정 기록
```

**핵심 원칙:**
1. 재대결 전 반드시 안내: "이 결과가 오늘의 최종 기록이 됩니다."
2. 재대결 이후에는 버튼 완전 사라짐 (서버 has_rematch = true 확인)
3. 광고 스킵/이탈 시 재대결 미진행으로 처리 (서버에서 확인)

## 5. 화면 IA (Information Architecture)

> 총 화면 수: **6개** (최소 구성)

```
홈 (/)
├── 플레이 (/play)
│   └── 결과 (/result)
│       └── 최종 결과 (/result/final)  ← 광고 후
├── 랭킹 (/ranking)
└── 내 기록 (/my-records)
```

---

### 5-1. 홈 화면 (`/`)

| 항목 | 내용 |
|------|------|
| **화면 목적** | 오늘 플레이 여부 확인 및 진입 유도 |
| **핵심 요소** | 오늘 플레이 상태 (아직 안 함 / 완료), 플레이 시작 버튼, 내 연승 현황 한 줄 표시 |
| **사용자 행동** | "오늘의 주사위 굴리기" 버튼 탭 → 플레이 이동 |
| **빠져도 되는 요소** | 전적 통계 상세, 공지사항, 랭킹 미리보기 |

**조건 분기:**
- 오늘 미플레이 → 플레이 버튼 활성
- 오늘 플레이 완료 (재대결 없음) → "오늘 결과 보기" + "한 번 더" 버튼
- 오늘 재대결까지 완료 → "오늘 최종 결과 보기" (재시도 버튼 없음)

---

### 5-2. 플레이 화면 (`/play`)

| 항목 | 내용 |
|------|------|
| **화면 목적** | 주사위 굴리기 인터랙션 |
| **핵심 요소** | 3D CSS 주사위 애니메이션 (사용자+AI 동시), "굴리기" 버튼, 결과 미리 보기 표시 |
| **사용자 행동** | 버튼 1회 탭 → 서버 요청 → 양쪽 주사위 동시 3D 스핀 → 결과 면으로 자동 전환 → 결과 화면 이동 |
| **빠져도 되는 요소** | 주사위 커스터마이징, 배경 선택, 만화적 이펙트 과도 연출 |

> 애니메이션은 1~1.5초 내 끝나야 함. 너무 길면 사용자가 이탈.

---

### 5-3. 결과 화면 (`/result`)

| 항목 | 내용 |
|------|------|
| **화면 목적** | 오늘 1차 결과 확인 + 재대결 유도 |
| **핵심 요소** | 내 주사위 숫자, AI 주사위 숫자, 승/패/무 표시, 재대결 버튼 (조건부) |
| **사용자 행동** | 결과 확인 → 만족 시 닫기 / 불만족 시 재대결 버튼 탭 |
| **빠져도 되는 요소** | 상세 통계, 오늘의 한마디 등 |

**버튼 노출 조건:**
- 이미 재대결을 완료했으면 버튼 없음 (서버 응답 기준)

---

### 5-4. 최종 결과 화면 (`/result/final`)

| 항목 | 내용 |
|------|------|
| **화면 목적** | 광고 후 재대결 결과 확정 + 오늘 종료 안내 |
| **핵심 요소** | 재대결 주사위 숫자 (내/AI), 최종 결과, "오늘의 기록이 확정되었습니다" 메시지 |
| **사용자 행동** | 결과 확인 → 홈으로 이동 |
| **빠져도 되는 요소** | 추가 재도전 버튼 (절대 불가), 공유 버튼 (V2) |

> "되돌릴 수 없음" 명확히 표시.

---

### 5-5. 랭킹 화면 (`/ranking`)

| 항목 | 내용 |
|------|------|
| **화면 목적** | 연승 TOP5 공개 + 경쟁 동기 부여 |
| **핵심 요소** | 연승 TOP5 리스트 (닉네임 마스킹 또는 익명), 내 현재 순위 (있으면) |
| **사용자 행동** | 랭킹 확인 → 홈으로 복귀 |
| **빠져도 되는 요소** | 복수 카테고리 탭, 역대 기록 |

---

### 5-6. 내 기록 화면 (`/my-records`)

| 항목 | 내용 |
|------|------|

| **핵심 요소** | 날짜별 결과 (승/패/무), 현재 연승 수, 최다 연승 기록 |
| **사용자 행동** | 기록 확인 → 홈 복귀 |

## 6. 기록/랭킹 설계

### 6-1. MVP에 포함할 랭킹 카테고리

| 카테고리 | MVP 포함 여부 | 이유 |
|----------|--------------|------|
| **연승 TOP5** | ✅ 포함 | 핵심 리텐션, "꾸준함" 반영, 단순 이해 |
| 연패 TOP5 | V2 | 부정적 지표 노출 이슈 있음 |
| 연속 무승부 TOP5 | V2 | 희귀 상황, MVP에 불필요 |
| 최고 숫자 연속 TOP5 | V2 | 운빨 지표, 리텐션 기여도 낮음 |
| 7일 평균 승률 TOP5 | V2 | 7일 누적 필요, 초반 데이터 빈약 |
| 누적 플레이 일수 TOP5 | V2 | 출석 기반, 서비스 성숙 후 의미 있음 |

> **MVP는 연승 TOP5 단일 카테고리만 운영.**  
> "꾸준히 이긴 사람"이 상위에 오르는 구조 → 사행성 아닌 꾸준함 강조.

### 6-2. 동률 처리 기준

**추천: 최근 달성자 우선 (Latest Achievement First)**

| 기준 | 설명 | 추천 여부 |
|------|------|-----------|
| 최초 달성자 우선 | 먼저 달성한 사람이 유지 | ❌ 신규 사용자 불리 |
| **최근 달성자 우선** | **나중에 달성하면 상위로** | ✅ 추천 |
| 보조 지표 적용 | 동점 시 누적 플레이 수 등 | 검토 필요 (복잡도 증가) |

MVP에서는 최근 달성자 우선으로 단순하게 처리.  
동점 시 `achieved_at` DESC 정렬.

### 6-3. 랭킹 갱신 방식

- 실시간 계산 금지 (매 조회마다 전체 테이블 집계는 비효율)
- `dice_leaderboard_cache` 테이블에 배치 업데이트
- 업데이트 주기: **1시간 단위** (Supabase Edge Function 또는 cron)
- 홈/랭킹 화면 진입 시 캐시 조회

## 7. 광고 UX 및 문구

### 7-1. 광고 진입점 설계

> **결과 화면 하단에 선택형으로 배치**

```
[결과 화면]
┌─────────────────────────────────┐
│  나: 3  |  AI: 5                │
│           패배                   │
│─────────────────────────────────│
│  현재 1연패                      │
│─────────────────────────────────│
│  ┌─────────────────────────┐    │
│  │  오늘 한 번 더 굴려볼게요  │    │  ← 이 버튼만 노출
│  └─────────────────────────┘    │
│  (짧은 동영상 시청 후 진행 가능)   │  ← 부연 설명
│─────────────────────────────────│
│  [홈으로]                        │
└─────────────────────────────────┘
```

**핵심 원칙:**
- 강제 팝업 없음
- 심리적 압박 문구 금지 ("지금 안 하면 기회 없어요" 등)
- 광고를 선택하지 않아도 홈으로 쉽게 이탈 가능
- "보상형 광고"처럼 보이지 않도록 문구 설계

### 7-2. 사행성 오해 방지 원칙

| 피해야 할 표현 | 권장 표현 |
|---------------|-----------|
| 한 번 더 도전하면 이길 수도 있어요 | 오늘 한 번 더 굴려볼 수 있어요 |
| 지금 이 기회를 놓치지 마세요 | 오늘의 기록을 바꾸고 싶다면 |
| 연승을 지킬 수 있는 마지막 기회 | 오늘은 여기서 끝낼 수 있어요 |
| 광고 보고 역전하세요 | 짧은 동영상 시청 후 한 번 더 굴릴 수 있어요 |
| 운명을 바꾸세요 | 오늘의 마지막 주사위 |

### 7-3. UI 문구 예시 (광고 관련)

**재대결 버튼:**
```
오늘 한 번 더 굴려볼게요
```

**버튼 하단 안내:**
```
짧은 동영상 시청 후 오늘 마지막으로 한 번 더 굴릴 수 있어요.
단, 이 결과가 오늘의 최종 기록이 됩니다.
```

**광고 완료 후, 재대결 직전 확인 안내:**
```
오늘의 마지막 주사위입니다.
이 결과는 오늘의 최종 기록으로 저장되며, 되돌릴 수 없어요.
```

**최종 결과 확정 후:**
```
오늘의 기록이 확정되었어요.
내일 다시 만나요.
```
