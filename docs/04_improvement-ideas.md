## 0. 현재 제품이 이미 가진 것 / 아직 약한 것

### 이미 있는 리텐션 뼈대

| 요소 | 상태 | 비고 |
|------|------|------|
| 하루 1회 제한 | ✅ | “오늘 아직 안 굴렸다” 미완료 훅 |
| 광고 후 재대결 1회 | ✅ | 패배·연승 위기 시 자발적 재시도 |
| 연승/연패/연무/같은번호/역전 랭킹 | ✅ | 경쟁 동기 |
| 연속 출석 데이터 | ✅ 집계만 | 홈에서 거의 안 보임 |
| 숫자별 반응 문구 60개 | ✅ | 결과 화면 한 줄 |
| 3D 주사위 + 랜덤 닉네임 | ✅ | 첫인상·익명 개인화 |
| 내 정보 통계 | ✅ | 승률, 눈 분포, 7일 기록 |

### 구조적 약점 (문서와 코드가 공통으로 가리키는 지점)

1. **플레이 후  intersession이 끊긴다.**  
   굴리면 할 일이 사라지고, “내일 다시 만나요”만 남는다. 홈이 대기실이 아니라 **빈 방**이 된다.
2. **재미의 레이어가 승/패 한 축에 몰려 있다.**  
   주사위는 운세·수집·이야기· rit ual에 잘 붙는데, 지금은 대결 점수판에 가깝다.
3. **출석·같은 번호·반응 문구가 “데이터”로만 존재한다.**  
   축하, 위기, 수집, 내러티브로 승격되지 않았다.
4. **푸시가 없다.** (Toss WebView 제약, PRD 제외 항목)  
   재방문은 **앱 재진입 시 눈에 띄는 미완료 상태**와 **끊기 싫은 개인 기록**에만 의존해야 한다.
5. **세션은 10~15초를 지켜야 한다.**  
   곁들임 요소는 본게임 앞에 끼워 넣지 말고, **결과 이후 / 내일 대기 화면**에 얹는 것이 안전하다.

### 절대 守수 (개선안도 이 선을 넘지 않음)

- 경품·포인트·쿠폰·현금성 보상 없음
- “한 번 더 기회를 산다 / 운명을 바꾼다 / 마지막 기회” 류 사행성·압박 카피 금지
- 아이템 버프로 승률을 조작하는 구조 금지 (PRD V1 제외 이유와 동일)
- 플레이 본편은 버튼 1회, 애니메이션 1~1.5초 유지

## 1. 흥미 유발 — “오늘 숫자가 궁금하다”

목표는 승패만이 아니라 **오늘의 숫자 자체**를 보고 싶게 만드는 것이다.

### 1-1. 오늘의 운세 레이어 (숫자 → 하루 한 줄)

이미 `lib/dice-reactions.ts`에 눈(1~6)별 반응 60개가 있다.  
지금은 결과 화면 회색 한 줄이라 **운세 앱의 핵심 감정**까지 가지 못한다.

**아이디어**

| 안 | 내용 | 왜 유효한가 |
|----|------|-------------|
| A. 눈 + 요일 시드 운세 | 같은 5라도 월요일/금요일 카피가 다름 | 매일 “오늘 문장”이 달라 보임 |
| B. 대결 결과 × 눈 조합 | `5로 승리` / `5로 패배` / `5 무승부` 톤을 분리 | 승패만 반복되지 않음 |
| C. 오늘의 키워드 1개 | “정돈”, “여유”, “한 걸음”처럼 명사 하나 | 공유·기억에 남음 |
| D. 금기 없이 가벼운 조언 | “오늘은 결정을 미뤄도 괜찮아요” | 운세 습관과 맞음. 점술·투자 조언은 금지 |

**구현 힌트:** 새 API 없이, 문구 테이블을 `(roll, result, weekday)` 키로 확장하면 된다.  
세션 길이는 늘리지 않고 결과 카드만 두꺼워진다.

### 1-2. 희귀 굴림 — “오늘만의 사건”

균일 1~6은 예측 가능해서 금방 익숙해진다.  
확률을 조작하지 말고, **해석만 희귀하게** 만들 수 있다.

| 사건 | 조건 | 연출 |
|------|------|------|
| 더블 | 나와 AI가 같은 눈 | “거울의 날”. 무승부를 실패가 아닌 사건으로 |
| 극단 | 1 vs 6 또는 6 vs 1 | “최대 격차”. 결과 화면에 전용 테두리 |
| 연속 같은 눈 | `same_num_streak >= 3` | 이미 집계 중. “3일째 4” 같은 개인 미스터리 |
| 첫 6 / 첫 1 | 생애 첫 최고·최저 | 한 번뿐인 기념 |
| 역전 | 1차 패 → 재대결 승 | 이미 통계 있음. 결과에서 “역전 기록”으로 호명 |

확률을 바꾸지 않으므로 공정성·심사 리스크가 낮다.

### 1-3. 주사위가 “누구인지” 보이게

지금은 나 vs AI, 면만 다르다.  
AI를 강화할 필요는 없고, **페르소나 한 겹**이면 충분하다.

- 고정 상대: “오늘의 상대, 회색 주사위”
- 요일 상대: 월=차분, 금=들뜬, 주말=느긋 (카피·색만 변경)
- 연승 중일 때만 대사가 조금 진지해짐  
  예: “연승을 의식하지 않기로 해요.” (압박이 아니라 인정)

Toss 금융 맥락과 맞추려면 캐릭터를 과하게 만화화하지 않는 편이 낫다.

### 1-4. 첫 방문 10초의 훅

PRD는 튜토리얼을 빼라고 했고, 그 판단은 유지한다.  
대신 **첫 결과 직후 한 문장**만 넣는다.

> “이 기록은 내일부터 이어져요. 끊기지 않게만 오면 됩니다.”

규칙을 가르치지 않고, **내일의 이유**만 심는다.

## 2. 리텐션 — “안 오면 아까운 것”

PRD의 핵심 문장: *어제 졌으니까 오늘은 이겨야 한다 / 연승을 끊기 싫다 / 오늘 운이 궁금하다.*  
여기에 **출석·미완료·마일스톤·시즌**을 얹는다.

### 2-1. 출석 스트릭을 홈 1급 지표로

`current_attendance_streak` / `max_attendance_streak`는 이미 갱신된다.  
그런데 홈은 승·패·무와 연승 뱃지 중심이라, **이기지 못해도 유지되는 이유**가 약하다.

**제안**

```
홈 (미플레이)
  [🔥 연속 방문 12일]
  오늘의 주사위, 아직 안 굴렸어요
  [오늘 주사위 굴리기]

홈 (플레이 완료)
  오늘 출석 완료 · 연속 13일
  다음 이정표: 14일까지 1일
```

출석은 승패와 독립이라 패배해도 “오늘은 지켰다”가 남는다.  
연승이 끊겨도 앱을 버릴 이유가 줄어든다.

**주의:** 출석 보상(포인트)은 넣지 않는다. 보상은 **숫자와 이정표 연출**뿐이다.

### 2-2. 이정표(Milestone) — 주간 클리어의 구체화

PRD V2에 “7일 연속 참여 뱃지”가 있다. 가장 ROI가 높은 확장이다.

| 이정표 | 조건 | 연출 |
|--------|------|------|
| 첫 굴림 | 1회 | 닉네임 탄생 카드 |
| 3일 | 연속 출석 3 | 작은 도장 |
| 7일 | 주간 클리어 | 홈에 일주일 점 7개 점등 |
| 14 / 30 / 100일 | 누적 또는 연속 | 희귀 테두리·칭호 (능력치 없음) |
| 연승 3 / 7 | 현재 연승 | 기존 뱃지 강화 |
| 같은 눈 5일 | same_num | “이 숫자에 홀린 주” |

뱃지는 **능력 버프가 아니라 수집 스티커**여야 한다.  
사행성 심사와 PRD의 아이템 제외 원칙을 지킨다.

### 2-3. 내일까지의 빈 시간을 “대기 연출”로

플레이 후 이탈이 정상이다. 문제는 재진입 시 홈이 심심한 것이다.

| 요소 | 설명 |
|------|------|
| KST 자정 카운트다운 | “내일 주사위까지 04:12:09” |
| 오늘 카드 고정 | 눈 + 키워드 + 출석 일수. 자랑·재확인용 |
| 내일 예고 한 줄 | “내일이면 13일 연속이 됩니다” / “연승 3이 이어집니다” |
| 미플레이 재진입 | 큰 주사위 + 짧은 문장만. 통계는 접기 |

카운트다운은 도박 압박(“지금 안 하면”)이 아니라 **내일의 의식**으로 쓴다.

### 2-4. 미완료 상태의 가시성 (푸시 대체)

[03_project-plan.md](./03_project-plan.md) 13-4: *Toss 앱 재방문 시 홈에 뱃지/알림*.

가능한 범위:

- 미니앱 아이콘/리스트 뱃지 또는 “오늘 미플레이” 서브텍스트 (Toss 정책 허용 시)
- 앱 내 홈 히어로를 미완료일 때 더 크게
- 랭킹·내 정보 진입 전에도 홈에서 한 번에 보이게

푸시가 없어도 **토스 앱을 연 순간 “아직이다”가 보이면** DAU가 움직인다.

### 2-5. 연승 위기 UX (광고 전환과 리텐션을 동시에)

플랜 문서도 “연승 3+ 패배 시 재대결 욕구 최고”라고 적었다.  
지금은 재대결 버튼이 결과와 무관하게 같은 톤이다.

**카피 분기 (압박 없이)**

| 상황 | 버튼 위 한 줄 |
|------|----------------|
| 연승 중 패배 | “연승 기록은 오늘 결과로 갱신돼요.” |
| 연패 중 패배 | “오늘은 여기서 끝낼 수도 있어요.” |
| 무승부 | “무승부도 오늘의 기록이에요.” |
| 승리 | 재대결을 숨기지 않되, 유도는 약하게 |

“지키지 않으면 끝장”은 금지. **사실 안내만.**

### 2-6. 무승부 규칙 재검토 (A/B)

PRD 4-2는 무승부가 연승을 끊는 현재 구현과, 연승을 유지하는 안을 둘 다 열어 두었다.  
리텐션 관점 가설:

- **끊는 방식(현재):** 규칙이 단순. 대신 무승부가 배신감.
- **중립 방식:** 연승 유저가 무승부에도 내일 온다.
- **타협안:** 연승은 유지, 별도 “무승부 삽입” 표시. 랭킹 점수는 연승만.

출시 후 무승부 다음날 재방문율을 보고 결정하는 것이 안전하다.

### 2-7. 주간 / 시즌 레이어

하루 단위만 있으면 7일 후 루프가 단조롭다.

| 주기 | 아이디어 | 보상 형태 |
|------|----------|-----------|
| 주간 | 7칸 출석 보드. 일~토 점등 | 보드가 가득 찬 시각적 완성 |
| 월간 | “이번 달 나의 눈” 히트맵 | 달력 스크린샷 욕구 |
| 시즌 | 4~6주 테마 (장마, 연말, 벚꽃) | 주사위 스킨·배경만 교체 |
| 주간 랭킹 | 이번 주 출석 일수 TOP | 누적 고인물만 유리하지 않음 |

주간 출석 랭킹은 PRD의 “누적 플레이 일수 랭킹”보다 **신규에게 공정**하다.

### 2-8. 패배·공백의 복귀 설계

연패와 결석은 이탈 지점이다.

- 연패 3+: “연패도 랭킹 부문입니다” — 이미 연패 랭킹이 있으므로 **호명만** 하면 된다.
- 1일 결석: 출석은 1로 리셋된다는 사실을 홈에서 담담히. 협박 금지.
- 7일+ 복귀: “다시 온 날의 주사위” 전용 카피. 패널티 없음.

처벌보다 **복귀 당일의 특별함**이 맞다.

## 3. 주사위와 곁들일 요소

본게임(대결)은 그대로 두고, 주사위가 **잘 붙는 장르**만 얇게 얹는다.

### 3-1. 수집 — 눈이 아닌 “오늘의 주사위 피부”

| 곁들임 | 설명 | 하지 말 것 |
|--------|------|------------|
| 시즌 스킨 | 색, 점 모양, 재질만 변경 | 스킨별 승률 |
| 눈 도감 | 1~6을 처음 뽑을 때 도장 | 희귀 눈을 더 자주 나오게 |
| 더블 도감 | 1-1 ~ 6-6 6칸 | 확률 조작 |
| 테마 주사위 | 주말만 둥근 점, 공휴일만 금색 점 | 유료 가챠 |

수집은 **보면 채워지는 것**이어야 한다. 뽑기의 느낌을 주면 심사·브랜드와 충돌한다.

### 3-2. 의식(ritual) — 굴리기 전후 0.5초

PRD는 과도한 만화 이펙트를 빼라고 했다.  
대신 **작은 의식**은 습관을 만든다.

- 굴리기 전: 주사위를 손가락으로 한 번 기울이기 (스킨십)
- 굴린 후: 눈이 멈춘 뒤 0.3초 정적
- 완료 후: 오늘 카드를 책상 위에 내려놓는 느낌의 레이아웃

길이를 늘리지 말고 **호흡만** 넣는다.

### 3-3. 기록의 시각화 — 운의 달력

내 정보의 7일 리스트는 회계장부에 가깝다.

- 7칸 또는 30칸 히트맵 (승=파랑, 패=회색, 무=점선, 결석=빈칸)
- 칸을 누르면 그날의 눈과 한 줄 운세
- “이번 주 내가 가장 많이 만난 눈”

통계 그래프(V2)를 차트 라이브러리 없이 **주사위 칸**으로 풀 수 있다.

### 3-4. 결과 카드 / 공유 (PRD V2)

소셜 공유는 MVP에서 뺐지만, **이미지 카드 자체**는 리텐션에 유용하다.

카드에 넣을 것:

- 닉네임, 날짜, 눈 vs 눈, 승패, 오늘의 키워드
- 연속 출석 또는 연승 (있을 때만)
- “오늘의 주사위”

1차: 앱 안에서 카드처럼 보이게 (저장·공유 버튼 없음)  
2차: 이미지 저장 / 시스템 공유  
카피는 자랑이 아니라 **오늘의 증표**.

### 3-5. 가벼운 질문형 곁들임 (대결 외 1비트)

매일 주사위 하나를 **질문의 답**으로도 읽게 한다.  
승패와 별도. 서버 판정 없음.

예:

- “오늘은 새로운 일을 미뤄도 될까?” → 눈 4 이상이면 그렇다, 같은 식의 **비결정적 해석**은 위험  
- 더 안전: 눈을 **척도**로만 보여 주고 해석은 사용자가 하게  
  “오늘의 추진력: ●●●●○○”

운세 앱 핵심을 가져오되, **예/아니오로 미래를 단정하지 않는다.**

### 3-6. 닉네임·호칭

랜덤 닉네임은 이미 있다. 편집은 V2.

곁들임으로 충분한 것:

- 이정표에 따른 **접두 호칭** (3일: 출근하는, 7일: 매일 오는, 30일: 자리 잡은)
- 랭킹 진입 시 이름 옆에 작은 점 1개
- 닉네임 재굴림 1회 (광고 아님, 가입 직후만) — 정체성 만족

능력치와 무관한 치장만.

### 3-7. 소리·햅틱 (WebView 허용 범위)

- 주사위가 테이블에 닿는 짧은 틱
- 더블일 때만 다른 틱 한 번
- 무음이 기본, OS 무음 모드 존중

없어도 되지만, 있으면 **오늘의 의식**이 된다.

### 3-8. 하지 않는 곁들임 (의도적 제외)

| 제외 | 이유 |
|------|------|
| 아이템, 가중 주사위, 리롤 아이템 | 사행성·복잡도. PRD와 충돌 |
| 멀티 실시간 PvP | 세션·인프라가 Toss 미니앱과 안 맞음 |
| 베팅, 포인트, 가챠 | 서비스 정체성 파괴 |
| 긴 스토리 모드 | 10초 완결 원칙 파괴 |
| 푸시 스팸 | 환경 제약 + 금융 앱 피로 |

## 4. 화면별로 얹으면 좋은 것

기존 6화면을 유지한 채 밀도만 올린다.

### 홈 `/`

| 상태 | 추가 |
|------|------|
| 미플레이 | 출석 N일, 오늘 안 굴림 히어로, (연승 중이면) 연승 한 줄 |
| 플레이 완료 | 오늘 카드 + 자정 카운트다운 + 다음 이정표 |
| 공통 | 최근 이정표 1개. 통계 요약은 접힌 채 유지 |

### 플레이 `/play`

- 규칙 설명 추가 금지
- 있다면: 주사위 기울이기 정도의 터치 피드백만

### 결과 `/result`

- 반응 문구 → 오늘의 키워드 + 2줄 운세
- 희귀 사건 테두리 (더블, 1vs6, 같은 눈 N일)
- 재대결 카피 분기
- 출석 이정표가 오늘 깨졌으면 결과에서 먼저 보여 주기

### 최종 결과 `/result/final`

- “오늘의 증표” 카드로 고정
- 역전이면 그 사실만 호명
- 내일 예고 한 줄

### 랭킹 `/ranking`

- 내 순위가 없으면 “출석 N일이면 주간판에서 보일 수 있어요” 정도의 **다른 판** 안내
- 주간 출석판은 별 탭으로 (데이터가 쌓인 뒤)

### 내 정보 `/my-records`

- 7일 리스트 위에 **점등 보드 / 미니 달력**
- 뱃지함 (모은 이정표)
- 눈 도감
- 닉네임 + 호칭

## 5. 우선순위 제안

세션 길이·심사·기존 스키마를 기준으로 나눈다.

### P0 — 데이터는 이미 있음. 보여 주기만 하면 됨 ✅ 반영

1. 홈에 **연속 출석**과 **다음 이정표까지 N일** ✅ `AttendanceBar`
2. 플레이 완료 홈에 **KST 자정 카운트다운 + 내일 예고** ✅ `MidnightCountdown`
3. 결과 문구를 `(눈 × 승패 × 요일)`로 확장 ✅ `lib/fortune.ts`
4. 더블 / 1vs6 / 같은 눈 연속을 결과에서 호명 ✅ `detectRareEvents`
5. 연승 중 패배 시 재대결 안내 문장만 분기 ✅ `RematchButton`

예상 공수: 작음. 테이블 변경 거의 없음.

### P1 — 리텐션 곡선이 바뀌는 것 ✅ 반영

1. 7 / 14 / 30일 **출석 이정표 뱃지** (능력치 없음) ✅ `BadgeShelf`
2. 내 정보 **7칸·30칸 운 달력** ✅ `LuckCalendar`
3. 결과 **오늘의 증표** 카드 (공유는 나중) ✅ 최종 결과 화면
4. 주간 출석 보드 (일~토) ✅ `WeekBoard`

`dice_streak_state`의 출석 컬럼 + 기존 `dice_daily_battle`로 대부분 가능.  
뱃지 해금만 컬럼 또는 JSON 하나면 충분.

### P2 — 세계관을 두껍게

1. 시즌·요일 주사위 스킨
2. 눈/더블 도감
3. 결과 이미지 저장·공유
4. 주간 출석 랭킹
5. 닉네임 호칭, 제한적 닉네임 재굴림
6. 무승부-연승 규칙 A/B

### 의도적으로 나중 / 안 함

- 푸시, 실시간 PvP, 아이템, 포인트, 가중 확률
- 튜토리얼 페이지
- 플레이 전 콘텐츠를 늘려 10초를 깨는 모든 것

## 7. 한 줄 방향

> **승패는 오늘을 닫고, 출석과 오늘의 숫자는 내일을 연다.**  
> 주사위 대결은 10초 그대로 두고, 그 주변에 운세·이정표·달력·증표만 얇게 곁들인다.

이 문서의 아이디어는 기존 4테이블 구조와 “재미와 기록이 유일한 동기” 원칙 안에서 선택하면 된다.

## 8. 중학생도 이해하게 — 이번에 코드가 한 일

어려운 말 없이 정리하면 이렇게 됩니다.

1. **표(데이터베이스)는 안 바꿨다.**  
   이미 “며칠 연속으로 왔는지”, “주사위가 몇이 나왔는지”를 저장하고 있었다. 그걸 홈과 내 정보에 **눈에 보이게** 꺼냈다.
2. **승패와 출석은 다른 점수다.**  
   져도 오늘 오면 출석 숫자는 올라간다. 그래서 “졌으니까 앱을 지운다”가 조금 줄어든다.
3. **같은 5라도 월요일이면 문장이 다르다.**  
   `lib/fortune.ts`가 숫자와 요일을 보고 문장을 고른다. 서버가 점괘를 내리는 것이 아니다.
4. **더블(나와 AI가 같은 눈)은 확률을 안 바꿨다.**  
   이미 나온 결과를 “거울의 날”이라고 **이름만** 붙인다.
5. **뱃지는 스티커다.**  
   7일 뱃지를 모아도 다음 주사위가 더 잘 나오지 않는다.
